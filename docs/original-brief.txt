 AI Subs
 Polished release project plan

 Working product name: AI Subs
 Prepared: October 2, 2026
 Status: Proposed specification; performance targets are not measured results.
 Primary reference machine: Linux, RTX 5090 with 32 GB VRAM, 128 GB system RAM.
 Secondary target: Apple Silicon Mac with M4 and 128 GB unified memory, after its inference
 backend passes a separate validation gate.

 Product outcome
 Open a video without useful subtitles, click Generate subtitles, and receive readable Japanese-
 to-English captions in the browser, including supported fullscreen players. Speech recognition and
 translation run on the user’s computer. A local companion handles models, installation, job
 recovery, and the subtitle library. No cloud inference is required.

 The polished product is a Chrome extension plus a desktop companion, not a heavyweight
 model running inside the extension.

 The most important correction
 Fast whole-episode generation and live tab capture are different products paths.
 Chrome tab capture provides the tab’s playing audio stream; it does not expose future audio or a
 downloadable copy of the episode. At normal playback speed, capturing an entire 25-minute
 episode takes approximately 25 minutes, even when inference is faster than real time. [S1]

 The earlier 1-3-minute episode estimate is therefore an unverified optimization target for a
 fully accessible source, not a promise for arbitrary streaming websites. This project includes
 both paths and clearly tells users which one is available.

 Release boundaries
 Ship Japanese-to-English first. Support one active capture session, a documented browser/player
 matrix, editable subtitles, caching, export, and a no-terminal setup flow. Defer universal website
 support, DRM workarounds, automatic character identity, dubbing, lyric-perfect karaoke, on-screen
 text OCR, and mobile browsers.

 1. Product experience and release scope

 First-run experience
 The user installs the extension and companion. Setup detects the inference device, checks free
 disk space and supported runtime versions, offers a tested model preset, obtains any required
 model-license acceptance, and downloads verified model files. A short included test clip confirms
 audio, inference, and captions. Explain the initial download separately from subsequent offline
 use.

 No command-line setup, manual Python installation, or pasted API key should be necessary for the
 supported release configuration. Unsupported hardware receives a specific explanation rather
 than an endless loading spinner.

 Watching an episode
 Clicking the extension starts a capability check, not silent recording. The extension identifies
 candidate video elements, lets the user select one when necessary, checks for existing usable
 subtitles, and reports one of three clear states: Generate ahead available, Live captions
 available, or Player unsupported.

 Generate-ahead mode displays preparation, recognition, translation, and timing progress
 separately. Playback can begin when an initial contiguous range is ready; the interface shows that
 range and prioritizes work near the playhead. Full completion remains available before playback.
 Live mode asks the user to play the episode and explicitly describes caption delay.

 Polished controls

   Area                                   Required behavior

   Caption appearance                     Font size, outline/background, vertical position, two-line layout, safe margins,
                                          and optional Japanese line.

   Playback                               Correct pause, seek, replay, playback-rate changes, episode changes, and
                                          supported fullscreen transitions.

   Correction                             Edit a cue, undo edits, rerun recognition or translation for a selected span, and
                                          adjust an approved glossary.

   Library                                Search local episodes, view coverage, resume jobs, export SRT/WebVTT, import
                                          an existing track, and delete retained data.

   Status                                 Show active mode, model readiness, verified coverage, current delay, errors,
                                          and a visible stop-capture control.

   Accessibility                          Keyboard operation, labeled controls, readable focus states, reduced-motion
                                          behavior, and persistent settings.


 Automatic show-memory entries are suggestions, not facts. Names and special terms become
 trusted glossary entries only after user approval or import from a user-trusted list. Do not promise
 that unreviewed memory automatically improves translation.

 Technical choices
 Use TypeScript for the extension and shared message schemas. Use Manifest V3, a content script
 for the player surface, and an offscreen document for live audio work. Chrome supports handing a
 tab-capture stream ID from the service worker to an offscreen document; captured audio must
 also be routed back to the audio output so the user continues hearing the episode. [S1, S8]

 Use a Tauri desktop shell with a small Rust native-messaging launcher and a packaged Python
 inference environment. Tauri documents bundling external binaries, which is the basis for
 packaging the local worker rather than asking users to install it manually. [S10]

 Use native messaging for application discovery, startup, and secure session bootstrap. Use an
 authenticated loopback WebSocket for binary audio and progress events. Keep the socket and
 audio graph in the offscreen document, not dependent on a long-lived service-worker timer.
 Chrome native messaging provides explicit extension-origin allowlisting. [S7]

 Use SQLite for jobs, cue revisions, settings, and glossary records; store larger temporary media
 separately. Start with one heavy GPU job at a time and prioritize the active playback session.
 Parallelize ASR and translation only after profiling memory and latency together.

 3. Input access and media-time correctness

 Source adapters
 Implement a common interface that reports source type, selected audio track, duration, access
 method, available ranges, and whether reading ahead is actually possible.

 Local-file adapter: a companion file picker grants an opaque media handle. Inspect the media,
 select the Japanese audio track when available, and decode only audio. A browser player must be
 explicitly matched to the imported file before applying its captions.

 Direct-source adapter: accept supported media URLs only through user-approved actions and
 origin-scoped access. Preserve content timestamps and validate redirects. A URL visible in a
 player is not automatically a fetchable full episode.

 Live-tab adapter: capture only after a user gesture. Audio capture is tab-wide, so choosing a
 video element does not isolate its audio from advertisements or other sounds in that tab. Warn
 about competing sources and suspend or reset when a tested adapter detects an ad or media
 replacement. [S1]

 Existing-track adapter: reuse an accessible Japanese transcript or matching English subtitle
 track before running speech recognition. Preserve original cue identity and timing.

 For later HLS/DASH support, require individual adapter tests for manifests, audio renditions,
 authorized access, timestamp discontinuities, expiration, and seek mapping. Do not simply
 concatenate unrelated fragments. No DRM bypass, credential dumping, or universal extraction
 claim is part of the design.

 Timeline is a first-class data model
 Store both media time and capture time. Every audio packet identifies the session, source,
 epoch, sequence number, sample rate, sample position, and the applicable media-clock anchor.
 Mark intervals containing a seek, stall, rate change, or discontinuity as invalid until a new anchor
 is established.

 A new episode, seek, or audio-track change increments the epoch. Late model results from an old
 epoch are discarded rather than displayed over the new scene. Save source-timed cues for replay;
 live rendering also records when a cue actually became available.

 Use media timestamps as the primary clock. A video-frame callback can supply the presented
 frame’s media time; it is a rendering aid, not a guarantee of sample-accurate audio alignment.
 Measure capture offset and drift separately. [S9]

 Required behavior
 If the user jumps to minute 12, cached subtitles display immediately there. In generate-ahead
 mode, uncached minute-12 audio becomes the highest-priority work. In live mode, the system
 resumes listening at minute 12 and never claims it can fill unheard minute-5 dialogue without
 another accessible source.

 Offline pipeline
 Decode to a consistent audio representation while preserving original offsets. Use speech-aware
 chunks, initially about 15-25 seconds with bounded overlap, adjusted to avoid cutting words.
 Recognize, deduplicate overlap, align the Japanese transcript, translate stable utterances, and
 produce readable timed English cues. Retain full chronological offsets even when silence is
 skipped for inference.

 Translate complete utterances or short coherent groups, not isolated audio packets. Batch
 independent work where the selected backend supports it. Do not load every candidate model at
 once or assume a 12B label predicts total VRAM use.

 Jev and Laya
 Neither is required for recognition, translation, or scheduling. Their documented role is typed
 decisions over supplied text/state rather than generating a subtitle transcript. Keep ordinary state
 machines in the main path. A later local Laya experiment could classify whether a transcript
 segment needs review, but must beat simple rules in measured quality and cost. [S11, S12]


 5. Subtitle quality, context, and editing

 Two distinct caption lifecycles
 Generate ahead: source audio arrives before viewing, so recognition, alignment, translation, and
 validation can all complete before the corresponding scene is displayed. Finished cues use media
 timestamps.

 Live: audio must arrive first. The system collects a phrase, stabilizes recognition, translates it, and
 displays the result late. Optional provisional text must be visually distinct and off by default. Keep
 live arrival time separate from the original speech interval so the exported track can be
 synchronized on replay.

 Do not promise sub-second final translation from the beginning of every Japanese sentence.
 Phrase completion is part of the latency budget. Pausing a tab also stops access to future playing
 audio; a subtitle-delay slider does not create an advance buffer.

 Context and terminology
 Supply a bounded number of prior confirmed dialogue lines and the approved show glossary to the
 context-aware translation adapter. Keep this transcript-derived context separate from user
 instructions and never give the translation model tools, shell access, or network access. Treat
 spoken instructions as dialogue to translate.

 Do not infer a speaker’s identity or relationship merely because a familiar anime name appears.
 Keep uncertain names reviewable. Changes to glossary entries create a new translation version
 and can retranslate affected cues without rerunning recognition.

 Subtitle assembly
 First align source-language words or characters to source audio. Then carry utterance timing into
 English and split or merge for readability. Do not try to force-align English translated words directly
 against Japanese speech.

 Proposed English layout defaults are at most two lines, a soft maximum near 42 characters per
 line, and a target of 12-20 characters per second. These are configurable product defaults, not
 universal standards. Flag cues that cannot meet them without losing meaning rather than silently
 deleting dialogue.

 Use deterministic checks for valid timestamps, missing/duplicate cue IDs, empty output, wrong-
 language output, excessive length, and unrequested commentary. Cap retries; preserve the
 original result and mark a span for review when retries fail. Do not invent a calibrated confidence
 percentage if the model or evaluation does not supply one.

 Minimal subtitle record

     cue_id, session_id, media_id, epoch
     source_start_ms, source_end_ms
     source_text, translated_text, target_language
     status: provisional | final | user_edited | needs_review
     model_revision, translation_config_hash, glossary_revision
     available_at_capture_ms, revision_number



 User edits override subsequent automated results unless the user explicitly requests replacement.
 Silence, screams, and overlapping speech remain evaluation categories, not situations in which
 the model is encouraged to guess.


 6. Browser rendering and fullscreen support

 Rendering hierarchy
 Native text track: first test adding a subtitle text track and timed cues to an accessible video
 element. The browser exposes addTextTrack() for this purpose. Validate its appearance and
 behavior on every player in the support matrix; do not assume the site leaves externally added
 tracks enabled. [S6]

 Custom overlay: use an isolated subtitle component attached within the player’s existing
 container. Shadow DOM can reduce style collisions, but is not a security boundary. Measure video
 bounds and safe areas, account for controls, and avoid intercepting ordinary player clicks.

 Fullscreen fallback: when the existing player container is fullscreen, render inside that subtree.
 When only the video element is fullscreen, prefer a validated native track. An explicit AI
 Fullscreen button may request fullscreen on an existing safe ancestor containing both video and
 captions. Avoid moving the video into a new wrapper by default; that can disturb the host player.

 Fullscreen requires more than a high CSS z-index: the fullscreen element occupies the top layer,
 and permission and user-activation requirements apply. Provide an in-page fallback when a
 supported fullscreen route is unavailable. [S5]

 Embedded and dynamic players
 For cross-origin iframes, request the relevant optional site permission and inject into the actual
 permitted player frame. all_frames applies to matching frames; it is not a bypass for inaccessible
 frames or permissions. [S13]

 7. Local security, privacy, and distribution

 Trust boundaries
 The web page is untrusted. Content scripts may report bounded player state, but cannot select
 arbitrary local paths, issue shell commands, request model downloads, or forward arbitrary HTTP
 requests to the companion.

 The native host allowlists the published extension ID, with a separate development configuration.
 Only a user-approved pairing step creates a session. Keep session credentials in extension-owned
 contexts, never in page DOM or page messages. Validate message origin, active tab/frame,
 session, epoch, and payload schema before forwarding.

 Bind the local backend to loopback only. Require session authentication and strict Host/Origin
 checks for HTTP and WebSocket connections; deny requests by default. Origin checks alone are
 insufficient. Expire tokens, limit request and queue sizes, and reject unauthenticated access
 before accepting audio. Native messaging and the browser-to-page separation are documented
 platform boundaries, not a substitute for application validation. [S7]

 For downloads, allow only explicit supported schemes and user-approved sources, validate redirect
 destinations, and prevent arbitrary server-side requests. Select local files through the companion
 and pass opaque handles. Run media parsers with bounded resources and argument arrays, not
 shell-interpolated commands.

 Data lifecycle
 Default live audio storage is a bounded RAM buffer, not an archive. A full-job temporary cache is
 visible, size-limited, and removed after completion or user cancellation according to policy. Delete
 job-specific buffers on stop. Explain crash-recovery retention and sweep abandoned temporary
 files at startup.

 Keep subtitles and glossary data only as configured in the local library. Never store page cookies,
 authorization headers, or expiring signed URLs in logs. Provide Delete episode data, Clear
 library, and Remove downloaded models as distinct actions.

 No telemetry by default. Diagnostic export is explicit, previewable, and redacted. Confirm that
 processing still works with outbound traffic blocked once models and media are present. The

 Shipping requirements
 Bundle the extension’s executable code; do not fetch scripts or WASM to execute from a CDN.
 Chrome’s Manifest V3 remote-hosted-code rules make this a release concern. Download model
 data through the companion with pinned revisions and integrity checks instead. [S14]

 Provide a privacy policy, permission explanations, license notices for every bundled model/library,

 when processing is local. [S15]

 Desktop updates must be authenticated, recoverable, and separate from model revisions. Sign/
 notarize packages where appropriate for the target platform, pin the tested runtime, and preserve
 a rollback path. Do not claim the NVIDIA backend automatically works on the Mac.

 modes. M2 validates display independently using saved subtitles. M3 follows a reliable display

 Do not make advanced routing models, automatic speaker naming, or broad site extraction part of
 the critical path.

 Staffing and planning
 Assign one accountable owner to each workstream and one release decision owner. Reserve
 bilingual review and real-browser test sessions explicitly. A build is not ready because the happy-
 path demo succeeded.

 Estimate engineering effort from completed M0 tickets, then size the remaining backlog and
 external release dependencies. Separate implementation work from store review, signing, model-
 download availability, and hardware validation. These external dependencies are not guaranteed
 turnaround times.

 11. Reliability, cache design, and release decision

 Durable and bounded processing
 Treat a job as a sequence of committed stages: ingest, segment, recognize, align, translate,
 validate, export. Store stage status and content/config hashes so restarting a worker does not
 redo completed work unnecessarily. Use atomic writes and idempotent event handling.

 Audio transport must use bounded queues with acknowledgement and backpressure. If live
 inference falls behind, reduce optional work or explicitly report delay. Never grow memory
 indefinitely or silently skip dialogue. Stop further ingestion when a job is cancelled; cancel queued
 GPU work where supported and discard late results otherwise.

 When memory is insufficient, retry a smaller batch or select an already-tested lighter preset with
 user-visible status. Do not silently replace the translation model halfway through an episode
 without tracking that change.

 Cache identity
 Match subtitles to media using source identity, duration, selected audio track, and a content
 fingerprint where available. Title plus episode number is insufficient: openings, recap cuts,
 advertisements, dubs, and alternate editions can change timing.

 Keep raw recognition, alignment, translation, user edits, and glossary versions separate. A font
 change must not rerun inference. A target-language or glossary change should invalidate only the
 relevant translation layer. An edited cue stays protected. A source fingerprint mismatch requires
 confirmation or a new job.

   Fullscreen/player conflicts            Native track first; tested container overlay; explicit unsupported state.

   Timeline drift or late results         Media anchors, offset tests, discontinuity epochs, strict stale-result rejection.

   GPU/runtime problems                   Pinned tested backend, measured memory budgets, sequential scheduling and
                                          known fallback presets.

   Wrong cached episode                   Fingerprint/version checks, duration and audio-track verification, user
                                          confirmation.

   Privacy or unsafe local                Pairing, loopback authentication, origin validation, narrow message capabilities,
   endpoint                               redacted diagnostics.

   Installation/update failure            Clean-machine tests, integrity verification, authenticated updates and rollback.


 Definition of done
 A fresh installation on the supported reference system generates and displays a complete
 evaluated episode, survives the full playback/lifecycle matrix, reports limits honestly, preserves
 user edits, exports a reusable track, deletes retained data correctly, and performs no undisclosed
 outbound inference.

 Recommended build order: prove local episode-to-SRT quality; prove browser timing and
 fullscreen using that SRT; add live capture; then finish installation, editing, recovery, security, and
 release validation.
